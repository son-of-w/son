## Outcome and implementation context

Add a proposed `son review` command that surfaces old/unverified facts, explicitly stale memories, unresolved old todos, possible duplicates, and decisions needing verification. Support explicit verified/stale transitions without deleting the underlying memory. Editing time is not evidence of freshness. Reuse provenance from [#2](2.md) and duplicate candidates from [#4](4.md) where available; avoid introducing competing mechanisms.

Inspect `src/activity.rs`, `src/report.rs`, `src/search.rs`, and the node model. Provide project/scope filters, bounded or paginated output, JSON, and a reason each item needs attention. Define how freshness appears in recall/context and whether it affects ranking; retain historical knowledge rather than silently hiding it.

Acceptance: controlled timestamps produce predictable review results; verification clears the appropriate review reason; explicit stale state survives edits and export/import according to the documented policy; completed todos are not reported as unresolved; review itself does not mutate memories.

Decision (William, 2026-11-11): Keep review ages configurable. Defaults are facts at 90 days since verification (creation if never verified), decisions at 180 days since verification (creation if never verified), and open todos at 30 days since creation. Ordinary edits do not reset the verification clock. These thresholds prompt review only: they do not automatically mark a memory stale, expire it, or delete it. Test the default boundaries and configuration overrides.

Decision (William, 2026-11-11): Explicitly stale memories receive labels only in v1, in recall/context and JSON. Stale status must not introduce a ranking penalty or hide results. Preserve the existing superseded-decision penalties independently: a node that is both stale and superseded still receives its superseded penalty. Add coverage demonstrating that stale status alone leaves ranking unchanged. The review-age and stale-ranking questions are settled.

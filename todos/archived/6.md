## Outcome and implementation context

Add an explicit output budget, proposed as `--max-chars`, to recall and context. Apply it across the complete response: hits, linked nodes, additional project context, and JSON bodies. Preserve valid JSON, usable IDs, and truncation/omission indicators with a route to `son show`. Define handling for a budget smaller than the minimum valid response; never silently exceed a promised hard limit. Leave full backup exports lossless.

Add an opt-in `--explain` view identifying actual match reasons: matched title/tag/body terms, synonym/prefix/typo expansion, project priority, ranking adjustments, and graph relationships. Derive explanations from the ranking computation rather than approximating them afterward. Inspect `src/search.rs`, `src/analyze.rs`, `src/render.rs`, and `src/app.rs`.

Acceptance: long Unicode content and large linked sets respect the documented budget; JSON stays parseable; essential identifiers and omitted-content signals remain available; explanation mode agrees with ranking and does not alter result ordering. Add ranking regression coverage and measure representative recall latency against the under-100-ms target.

Decision (William, 2026-11-11): Budgeting is opt-in for v1 via `--max-chars <number>` on recall/context. Without the flag, preserve existing output behavior, including existing per-body clipping; do not introduce a default aggregate budget. With the flag, the complete response, including linked/additional context and serialized JSON, must fit the requested budget. Document the character-counting rule and test both budgeted and unchanged unbudgeted output. There is no default budget size to choose because callers explicitly supply it. The budgeting questions are settled.

## Result

`--max-chars <number>` on `son recall` and `son context`. Counting rule: Unicode code points of everything written to stdout, line ends included. The renderer (`src/render.rs`) builds the answer as text in a fixed list of forms, fullest first, and prints the first that fits: (recall) all; without the collection extras; without linked nodes; bodies at 400, 200, 100, 50, 0 characters; one line for each match; fewer matches down to one; ids only, down to one id. (context) details at 600, 300, 150, 60, 0; 8, 5, 3, 2, 1 items in a section; counts only; the collection's name only. If the shortest form does not fit, the command fails with `invalid_argument`, says how many characters the shortest answer needs, and prints nothing. Markdown ends with a "(shortened to fit --max-chars: ...)" line; JSON is printed on one line with `truncated`, `omitted` and `body_cut`, and linked nodes in a short form. Without the flag the output is as before (per-body cut at 800 in recall; no total limit). Export is not touched.

`--explain` on `son recall`. `search::ranked` records, as it computes, the text score and each multiplication it applies (`Hit::why`), and where each query word was found and how (`exact`, `synonym`, `prefix`, `typo`; in `title`, `tags` or `body`). Markdown prints two "why:" lines for each match and one for the linked and "also" lists; JSON adds `why` to each hit. The order is the same with and without the flag.

Latency, release build, 3000 nodes with 80-word bodies, whole process with `--explain --max-chars 2000`, 30 recalls on an Apple-silicon Mac: median 23 ms, 95% under 28 ms, slowest 67 ms. Target: under 100 ms.

Tests: `max_chars_bounds_the_whole_answer` (seven budgets, markdown and JSON, recall and context, multi-script bodies, 12 linked nodes; too-small budgets), `explain_says_why_without_changing_the_order` (tests/cli.rs); `the_explanation_is_the_score_and_recall_is_fast` (tests/ranking.rs).

## Outcome and implementation context

Add a proposed `son review` command that surfaces old/unverified facts, explicitly stale memories, unresolved old todos, possible duplicates, and decisions needing verification. Support explicit verified/stale transitions without deleting the underlying memory. Editing time is not evidence of freshness. Reuse provenance from [#2](archived/2.md) and duplicate candidates from [#4](archived/4.md) where available; avoid introducing competing mechanisms.

Inspect `src/activity.rs`, `src/report.rs`, `src/search.rs`, and the node model. Provide project/scope filters, bounded or paginated output, JSON, and a reason each item needs attention. Define how freshness appears in recall/context and whether it affects ranking; retain historical knowledge rather than silently hiding it.

Acceptance: controlled timestamps produce predictable review results; verification clears the appropriate review reason; explicit stale state survives edits and export/import according to the documented policy; completed todos are not reported as unresolved; review itself does not mutate memories.

Decision (William, 2026-11-11): Keep review ages configurable. Defaults are facts at 90 days since verification (creation if never verified), decisions at 180 days since verification (creation if never verified), and open todos at 30 days since creation. Ordinary edits do not reset the verification clock. These thresholds prompt review only: they do not automatically mark a memory stale, expire it, or delete it. Test the default boundaries and configuration overrides.

Decision (William, 2026-11-11): Explicitly stale memories receive labels only in v1, in recall/context and JSON. Stale status must not introduce a ranking penalty or hide results. Preserve the existing superseded-decision penalties independently: a node that is both stale and superseded still receives its superseded penalty. Add coverage demonstrating that stale status alone leaves ranking unchanged. The review-age and stale-ranking questions are settled.

## Result

`son review [--collection] [--type] [--fact-days] [--decision-days] [--todo-days] [--limit] [--page]` (`src/review.rs`). Reasons, with their JSON codes:
- `stale`: the node was marked with `son stale`.
- `not_verified`: a fact (90 days) or decision (180 days) whose last verification, or creation when never verified, is older than the limit. Strictly older: at the limit less one hour it is not listed, at the limit plus one hour it is. A stale node is listed as stale only; a superseded decision is not listed for age.
- `old_todo`: a todo with status `open` created more than 30 days ago. Done and dropped todos are never listed.
- `possible_duplicate`: `search::duplicates` (the same test as `--check`) finds an older live node; listed on the newer node only; not listed when the two have any link between them.

Order: stale, then possible duplicates, then the most overdue. Limits: flag, else `SON_REVIEW_FACT_DAYS`, `SON_REVIEW_DECISION_DAYS`, `SON_REVIEW_TODO_DAYS`, else the defaults. Review does not write to nodes; the limits only choose what is listed.

Stale state: schema version 9, `nodes.stale_at` and `nodes.stale_note`. `son stale <id> --reason "<text>"` sets it, `son stale <id> --clear` removes it, and `son verify` removes it (a node that was checked and is right is not stale). `son edit` does not touch it. It is part of the history snapshot (undo restores it) and of the JSON export; on import it travels with the node when the file's copy is newer. Label `STALE` in recall, context and show; no ranking change. A node that is stale and superseded keeps the superseded penalty.

Tests (tests/cli.rs): `review_lists_what_needs_attention_and_changes_nothing` (timestamps set in the database: both sides of each default limit, flag and environment overrides, edit against verify, done todos, stale through edit, export and import, duplicates), `a_stale_mark_does_not_change_the_ranking` (same order and same scores before and after).

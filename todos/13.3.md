# 13.3 — Implement offline-first pull and push sync

Priority: P2
Status: Deferred — future version
Parent: [#13 — Version 2](13.md)
Priority assigned as the P2 default during migration.

## Outcome and implementation context

Implement `son sync` and an HTTP client for the parent API sketch. Pull central records into the local database with origin labels; push only shared local records. Sync is separate from recall, which never waits on the network. Resolve bearer credentials from macOS Keychain or an environment variable, outside the database. Preserve globally unique IDs, revisions, tombstones, provenance, and relationships; activity logs remain local and unsynchronized.

The full proposal, API sketch, schema foundations, and original open questions are in [the parent design](13.md). They are proposals, not settled v2 decisions. This migration does not authorize implementation.

## Dependencies

Requires #13.1, #13.2, and an agreed protocol with #13.5. Read v1 history/purge (#7), backups (#9), and idempotency (#8).

## Acceptance and validation

Local recall works fully offline before and after sync. Repeated sync does not duplicate records. Failed or interrupted sync does not corrupt local state or lose progress. Tests cover private-data exclusion, remote origin, revisions/tombstones, conflicts under the agreed policy, and retry behavior. Reconcile explicit purge and full restore with sync cursors before shipping.

Run the repository checks in [CLAUDE.md](../CLAUDE.md) and isolate test databases, configuration, and credentials.

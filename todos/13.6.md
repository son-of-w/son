# 13.6 — Support MCP if needed: a local MCP service and a remote MCP store

Priority: P2
Status: Deferred — future version
Parent: [#13 — Version 2](13.md)
Added by William, 2026-11-11. This todo does not authorize implementation.

## Outcome and implementation context

Version 2 supports MCP (Model Context Protocol) if it is needed. William named two forms:

* **Local MCP service.** `son` can run an MCP service on the user's machine. Agents that use MCP tools then reach the same local database through MCP calls (recall, remember, todo, and the other commands) and do not need the shell.
* **Remote MCP.** A remote MCP service stores the data for the users. An agent with no local `son` binary or no shell (for example a hosted agent) can then read and write memory through it.

"If needed" is part of the request: first show that MCP is necessary. The shell command already works for agents that can run commands, so MCP must add something for agents that cannot, or for a remote store.

The full version 2 proposal is in [the parent design](13.md). The items there are proposals, not settled decisions.

## Dependencies

The remote form overlaps the central-store server and API in [#13.5](13.5.md) and sync in [#13.3](13.3.md): decide whether the remote MCP is a second interface on that server or a separate service. Sharing rules from [#13.2](13.2.md) and remotes from [#13.1](13.1.md) apply to data that leaves the machine. The local form depends only on version 1 behavior.

## Acceptance and validation

* The need is confirmed with William before implementation starts.
* The local service gives MCP tools with the same results and the same `--json` record shapes as the commands, on macOS, Linux and Windows.
* Recall through the local service does not wait on the network.
* The remote service enforces authentication and the agreed permissions server-side. No secret is stored in the database.
* The `son` command continues to work with no MCP service running.
* Setup for each supported agent is documented, and `son init` can write the MCP configuration if that is agreed.

Run the repository checks in [CLAUDE.md](../CLAUDE.md) and isolate test databases, configuration, and credentials.

## Deferred questions

Owner: William. Resolve these before implementation.

* Is MCP needed? Which agents or users cannot use the shell command?
* Local service: started by the agent on stdio (`son mcp`), a long-running local HTTP service, or both?
* Remote MCP: the only store for a user who has no local database, or a second interface on the central store that still syncs with local databases?
* Who hosts the remote service: self-hosted only, or a hosted offer?
* Which commands become MCP tools, and does `son init` configure MCP for each agent?

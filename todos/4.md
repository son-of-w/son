# 4 — Add duplicate checks and explicit memory merging

Priority: P2
Status: Open
Legacy ID: V1-04
Priority assigned during migration on 2026-11-11; adjustable by the user.

## Outcome and implementation context

Add a proposed `son remember --check` path that returns likely existing matches before a write, using local deterministic matching. Define its write behavior clearly so scripts cannot mistake a preview for a saved node. Add a proposed `son merge` command with explicit source and survivor IDs. Similar wording is only a candidate signal, not permission to merge. Preserve useful body content, tags, links, and provenance; keep an audit trail and a way to trace the old IDs.

Inspect `src/analyze.rs`, `src/search.rs`, `src/store.rs`, `src/transfer.rs`, and CLI dispatch. Merge atomically, handle duplicate/self edges and supersession relationships, and coordinate reversibility with [#7](7.md). Explain match reasons and support JSON. Update generated instructions to use the agreed workflow.

Acceptance: checking leaves the store unchanged under preview semantics; meaningful duplicates are surfaced without merging distinct decisions; merge does not lose references or evidence; failed merges roll back; retries do not duplicate links; deleted and cross-project nodes have explicit handling.

Decision (William, 2026-11-11): `son remember --check` is strictly read-only, including when no duplicates are found. It only reports candidate matches; saving, editing, and merging require separate explicit operations. Do not create a project/node, update metadata/indexes, or write an activity event for this preview. Ensure the check path does not create or migrate a database as a side effect; an absent store should yield an empty preview without creating it. Test both matching and no-match cases for absence of persistent changes.

Decision (William, terminology revised 2026-11-11): Allow cross-collection merges only with an explicit `--cross-collection` flag (replacing the earlier proposed `--cross-project` name under [#5](5.md)). Keep the chosen survivor's collection and preserve provenance and links from both memories. Without the flag, reject a merge across collections without partially changing either memory. Test rejection without the flag, successful opt-in, survivor collection retention, and preservation of provenance and links.

Decision (William, 2026-11-11): When memory bodies conflict, require the caller (agent or user) to supply the resolved body explicitly. Do not automatically select or concatenate conflicting content. Preserve both original memories in history, coordinating with [#7](7.md); capture the originals and apply the merge atomically. Reject an unresolved conflict without partial changes. Tests must show that the caller's resolved text is saved and both originals remain inspectable in history. The duplicate-preview, cross-project merge, and conflicting-body questions are settled.
